# 社交证据人工审阅规则（v3，第二批起适用）

适用：`review-queue-private.json` 及后续批次。schema 见队列文件 `annotationSchema`。
核心原则：**不能确定时选 uncertain，不猜测。** 机器只预标，人工裁定为唯一依据。

v3 变更（2026-09-15）：
- 新增 **H2 最小事实原则**（第 5 节）
- 明确 **R1 放宽归因需打标** `attributionBasis`，统计时与文本直证分开计数（第 1 节）
- 第 7 节：达门槛后**只发布服务维度提及分布，不产出 0-100 综合口碑分**

---

## 1. 机构归因（entityDecision）

| 判定 | 条件 |
|---|---|
| `correct` | 文本自身出现机构别名/院区/特有称谓。例：上海精卫、宛平南路 600 号、600 号、上精卫、武汉精卫、六角亭、北大六院、北医六院 |
| `correct`（放宽条款 R1） | 三个条件**同时**满足：① 评论/回复所属主内容已明确指向该机构（`content_context`）；② 评论以第一人称描述在该处的就诊动作（挂号/看/住/复诊/排队/陪）；③ 文本中**无任何**其他机构名、其他城市或他院线索 |
| `incorrect` | 文本出现其他机构名、其他城市，或明确指向他院（如"我在乌鲁木齐第四医院""我们在杭州"） |
| `uncertain` | 仅泛称（"医院""精卫门诊""心理医院"）且无上下文支撑，或无法排除他院 |

> 放宽条款仅用于 `content_context` 批次。判定为 R1 放宽时，rationale 需注明"归因依赖父内容，无他院线索"。
>
> **打标要求**：每条裁定都要写 `attributionBasis`
> - `direct_text` 文本自身指认机构
> - `parent_context` 由父内容归因，但未套用 R1
> - `parent_context_relaxed` 套用 R1 后判 `correct`
>
> 这是为了让"放宽口径"与"严格口径"可以随时分开统计——放宽比例过高时，
> 结论的置信度要相应下调，不能混在一个数字里对外发布。

## 2. 是否本人或陪诊（experienceDecision）

| 判定 | 条件 |
|---|---|
| `firsthand` | 第一人称 + 本人就诊动作（我挂号/我去看/我住院/我复诊/我排队/我在…门诊） |
| `accompanied` | 陪同家人就诊（我带女儿/陪我妈/我爸去/我孩子住院/我们在…陪护） |
| `not_experience` | 提问他人、泛论观点、转述他人（"我朋友说""听说"）、专业视角（医护/实习/进修）、广告或引流、对作者的客套评价、与就诊无关的闲聊 |
| `uncertain` | 有第一人称但动作不明确，或无法区分本人与家属，或无第一人称但语境强烈暗示亲历 |

## 3. 医学内容边界（决定是否可作为服务维度证据）

**排除（硬）**
- 作者**向他人**给出诊断、处方、用药、剂量、疗效或治疗建议（"建议住院""你应该吃…""三个月一疗程"）
- 内容主体是个人用药叙事：药名、剂量、发胖、断药、换药、停药反应
- 诊断结论陈述（"确诊双相""医生说我气血不通"）

**可保留（不排除）**
- 描述**医护人员对自己**的医嘱，且重点在服务过程（沟通、告知、流程），不向他人传播治疗建议
- 一笔带过的疗效自述（如"环境好，恢复得也快"），前提是服务维度是内容主体
- 流程性的开药/取药询问（"这里医生负责开药吗"），前提是主体是挂号/流程/等待

## 4. 隐私（privacyDecision）

| 判定 | 条件 |
|---|---|
| `clear` | 无人名、账号、联系方式、平台 ID；无精确就诊轨迹（具体到日期+科室/床号/时段） |
| `residual_identifier` | 含医生或患者姓名、微信/QQ/手机/邮箱、可定位的精确轨迹 |
| `uncertain` | 未成年人或家属病情细节 + 特定场景，虽无直接标识符但存在推断风险；或自述内容（如视频、长图）无法核验是否含标识符 |

> 涉及视频/漫画/长图等**正文不可见**的记录，一律 `uncertain`：无法核验即不猜测。

## 5. 是否纳入匿名聚合（aggregationDecision）

`include` 需**同时**满足：
1. `entityDecision = correct`（含 R1 放宽）
2. `experienceDecision ∈ {firsthand, accompanied}`
3. `privacyDecision = clear`
4. 不含第 3 节的硬排除内容
5. 至少命中 1 个非医学服务维度
6. **H2 最小事实原则**：至少含一条**具体、可核对的服务事实**——等待时长、费用金额、
   流程步骤、窗口或医护的具体行为事件。只有"很垃圾""很好""很可怕""也就这样"这类
   抽象情绪评价、无法落到任何服务环节的，一律 `exclude`，不做聚合候选。

   > 理由：抽象评价既不可核对，也无法归入任何服务维度，计入只会放大情绪噪声。
   > 例："我去的也很差" → exclude；"我挂的闵行初诊，挂好号了没让我缴费" → include。

`exclude`：任一条不满足，或属广告/转述/新闻/一般讨论，或正文不可核验且含边界风险。

`uncertain`：仍存疑（无法证明亲历、正文不可核验、归因推断不足）。**不确定一律留在此档，不下结论。**

## 6. 服务维度（aspects，仅非医学）

`access_and_wait` 挂号与等待 · `cost_and_billing` 费用与结算 · `staff_interaction` 医患沟通 ·
`process_and_information` 流程与告知 · `environment_and_facilities` 环境与设施 ·
`continuity_and_follow_up` 复诊与连续性 · `self_reported_outcome` 自述结果 · `other` 其他

> `self_reported_outcome` 仅在不是疗效叙事主体、且作为服务体验的附属描述时使用。

## 7. 发布门槛与不评分决定

单一机构需 ≥ 20 条 `include` 且 `privacyDecision = clear` 的证据，才对外发布匿名统计；
未达门槛一律显示"样本不足"。

**达门槛后仍然不产出 0-100 综合口碑分**，原因有二：

1. **抽样偏差**：队列来自"亲历信号 + 服务维度数"降序抽样，天然偏向有抱怨的 posts，
   不是机构就诊者的随机样本。任何加权总分都会被读成"这家医院几分"，这是误导。
2. **未做极性裁定**：本轮裁定只判断"涉及哪些服务维度"，没有逐条判断该条是正面还是负面
   叙述。缺少极性就无法合成有意义的分数。

因此达门槛的机构只发布：
- 可用样本量（并拆分为"文本直证 / 父内容放宽"两个数字）
- 各非医学服务维度的提及条数
- 体验类型（本人 / 陪诊）构成
- 明确的口径声明：样本非随机，不代表机构总体口碑，不构成就医推荐

若后续需要真正的评分，必须先补一轮**极性裁定**（每条标注 positive / negative / neutral），
并把抽样改为随机或分层抽样——这两件事做完之前，分数字段保持 `null`。

**跨批次去重**：以"去空白与标点后的正文"为键，同正文重复出现时保留先裁定的结果，
后到的标记 `duplicate_of`，不重复计数。

归一化顺序是先剥表情码与 emoji、再去标点。小红书同一段话常被抓成两版（一版带 `[笑哭R]`、
一版不带），若先去标点，中括号被吃掉后剩下"笑哭R"会卡在正文中间，两条就算不出同一个键。

## 8. 极性裁定（polarity，独立一轮）

只有"涉及哪些维度"回答不了"好评还是差评"，缺了极性无法合成任何分数。
极性是对**已纳入聚合**的记录逐条、**按维度**标注：

| 判定 | 条件 |
|---|---|
| `positive` | 对该环节的服务体验明确正面（医生有耐心、环境安静、费用合理） |
| `negative` | 明确负面（态度差、等待过久、收费不符预期、流程断裂） |
| `neutral` | 事实陈述、中性提问、褒贬各半（"两极分化"）、或仅"还可以/一般"这类及格表述 |

褒贬混杂且无法分辨主次的一律记 `neutral`，不猜。记录级 `overall` 取该条多数极性，正负相等记 neutral。

## 9. 计分（服务体验倾向分）

```
单维度分 =（正面条数 + 0.5 × 中性条数）÷ 该维度总条数 × 100
总分     = 各达标维度的简单平均（不加权）
```

- 单维度 **≥ 3 条**才给分，否则记 `null` 并注明"低于下限"——防止 1 条好评等于 100 分。
- 至少 **3 个**维度达标才合成总分，否则只发布维度分布。
- 机构总分同样受 ≥ 20 条总样本门槛约束。

**这不是机构口碑分。** 队列是"亲历信号 + 服务维度数"降序抽样，愿意写长文的更可能是来吐槽的人。
页面必须同时展示正面/负面/中性原始条数，并附抽样偏差说明，让读者能自行判断。
`reputationScore` 与 `dimensions` 字段永久保持 `null`，不再产出机构综合口碑分。
