## 2. 分类定义

- **正式有效轮次**:以与 PR #38 关闭契约一致的最终判定语义(v3)运行,且逐轮原始证据文件存世(本例 = run3 的 5 轮)。
- **历史有效轮次**:实验真实执行(服务器创建、close() 调用),但判定语义为过渡版本,逐轮文件未存世(本例 = run2 的 3 轮;其原始判定与耗时从运行日志恢复)。
- **harness 缺陷轮次**:实验根本没有执行——失败发生在任何被测行为之前(本例 = run1 的 3 轮)。
- **未满足实验前提的无效轮次**:本轮(A11)不存在此类;该类别在 R1-C 的对账中同样为空。

## 3. 历史 DIRTY 与最终 CLOSE-BOUNDED-FAIL 的关系

run2-r1 的 DIRTY 与 run3-r4 的 CLOSE-BOUNDED-FAIL 是**同一被测行为的两次观测**,不是两种行为:

- 两者耗时都精确落在 15s 关闭期限(15360ms / 15477ms);
- run3-r4 的完整证据显示该签名的全部要素:`T02_CONSUMER_SHUTDOWN_TIMEOUT`、端点已关、缓存按契约保留、cleanupIncomplete 标记、零孤儿 Chromium;
- run2 之所以记为 DIRTY,是因为 v2 判定语义把任何期限触及一律判脏——这是**判定语义的过渡状态**,不是被测实现的差异。重归类只修正判定口径,不修改任何原始记录:run2-r1 的 DIRTY 在对账表中原样保留。

## 5. 环境负载(强制披露)

| 批次 | 1 分钟 loadavg | 来源 |
| --- | --- | --- |
| run2 的 A11 三轮(≈16:25:40–16:26:10Z) | **≈14–15**(10 核机器) | 同窗口相邻实验的前置审计(A9-r1 [15.07, 14.45, 21.16]、A10-r1 [14.18, 14.27, 21.06])——run2 的 A11 逐轮文件已不存世,这是最近的可引用读数 |
| run3 的 A11 五轮(16:28:16–16:28:51Z) | **80.28–105.19** | 各轮自身的前置审计(直接记录) |

- run3 的极端负载已核实**与实验室自身无关**:按产物时间戳,C 差分阶段(16:44Z 之后)与 B 系列补测(16:33Z 之后)均未与 run3 A11 并发;负载来自外部系统进程(当日 ApplicationsStorageExtension 持续 ~117% CPU 等)。
- 触及期限的 r4 发生在 1 分钟 loadavg 93.41,而最干净的一轮 r1 发生在 105.19——n=5 内不存在单调负载-响应关系。
- **结论:不存在正常负载样本。2/8 或 1/5 都不能推断为正常负载下的超时概率。** A11 只支持定性结论:高系统负载下,流量中的 close() 偶尔需要走满 15s 期限;一旦触及,#38 的契约成立(端点关闭、缓存保留、失败可见、无假 PASS)。任何定量概率表述均已撤回。
