# TEMP-DIR-CLEANUP-PROOF — 临时目录清理证明(R1)

独立 Review 从正式逐轮 `newTempCaches` 只能直接确认 12 个新增目录,而报告称 20 个。本文件与机器可读的 `evidence/TEMP-DIR-LEDGER.json` 共同给出 20 = 12 + 8 的完整对账、逐目录记录与清理证明。

## 1. 对账闭合

| 记录类别 | 数量 | 身份 |
| --- | --- | --- |
| 正式轮具名记录(逐轮 osAudit `newTempCaches` 差分,证据文件存世) | **12** | 12 个目录名全部具名:A9 三轮各 2 个(probe-runtime + vite-cache,来自中途 SIGTERM 的 case worker)、A14 五轮各 1 个(vite-cache,来自 SIGKILL 的 probe worker)、A11-r4 一个(期限轮按契约保留的缓存) |
| 失失记录的匿名条目 | **8** | 目录名不可恢复(见 §2),但类别与归属有结构性依据 |
| **合计** | **20** | **与磁盘差值(112 − 基线 92 = 20)精确闭合** |

去重依据:12 个具名条目来自互不重叠的已完成轮审计;8 个匿名条目恰好对应全部记录不可恢复的运行。一个目录不可能同时出现在两集合——具名需要完成的轮审计,而存世的完成轮审计已全部枚举。

## 3. 清理操作与最终结果

```
# 清扫命令(仅匹配本实验会话日期创建的目录)
find <tmpdir> -maxdepth 1 -name 'symgene-t02-*' -newermt 2026-10-24 -exec rm -rf {} +

清扫前匹配数:20        清扫删除:20
清扫后 symgene-t02-* 总数:92   ==   实验前记录的基线 92
```

- 基线 92:会话首次 osAudit 的 `symgeneTempCaches` 快照(属更早会话,本实验从未触碰)。
- R1 会话开始时复核:symgene-t02-* = **92**、t02-faultlab-* = **0**——清扫结果在整改时点仍然成立。
- 实验目录以外被触碰的资源:**0**。harness 挂起后遗留的本实验自有进程(2 个)由操作者点杀,与目录清扫分开记录。

## 4. 状态标记

- 12 个具名条目:`CLEANED`(名字级验证:清扫前在磁盘快照中可见,清扫后总数回到基线)。
- 8 个匿名条目:`CLEANED-IDENTITY-UNVERIFIED`(计数级验证:总数闭合;名字不可考,无法逐名确认)。
- 没有 `UNREMOVED` 条目;没有任何非本实验资源被删除。

## 5. OS 快照检测的能力边界

pgrep / 端口探测 / 目录快照只能证明**审计时刻**的状态。它们不能证明:(a) 两次审计之间创建又删除的目录;(b) 在审计前死亡的进程所建目录的名字(只能给出类别与数量);(c) 受审计前缀之外的资源;(d) 两次审计之间外部行为者对临时根的改动。因此:具名条目的清理是名字级证明;匿名条目的清理只能是计数级证明,并如实标注 `CLEANED-IDENTITY-UNVERIFIED`。
