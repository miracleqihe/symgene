# 心鉴 / Sym Gen 开发历程与 AI 协作交接

> 文档用途：帮助合作者快速理解项目为什么会变成现在的样子、哪些方案已经验证、哪些方案被明确否定、哪些工作仍未完成，以及后续使用 AI 修改项目时应遵守的设计与工程约束。
>
> 本文记录的是 `local-ui-redesign` 分支截至 2026-07-31 的开发状态。它既是历史记录，也是后续设计决策的保护栏。代码仍应作为当前实现细节的最终依据。

## 1. 项目现在是什么

“心鉴 / Sym Gen”是面向公众的精神与心理健康公益知识库，主要提供：

- 114 个精神药物词条；
- 122 个疾病科普词条；
- 122 个教学性案例；
- 4 项公开网络资源；
- 浏览器本地运行的自然语言描述式检索；
- 高风险描述的优先安全提示；
- 仅在本地开发环境开放的新增、编辑、删除与本地存储。

它不是诊断工具，也不提供处方或个体化医疗建议。公开版本保持只读，原始书籍、PDF、OCR 文本和提取中间文件不能进入公开仓库。

当前产品采用 React + Vite，没有引入路由库。主页面、药物、疾病、案例和资源之间由 `activePage` 状态切换。页面转场由 `AnimatedPresence` 管理，详情切换使用同一套分层思想。

## 2. 当前版本应被视为“已确认”的部分

以下部分已经经过多轮视觉反馈和浏览器验证。除非合作者明确要求重新设计，否则 AI 不应主动推翻：

### 2.1 品牌与首页

- 中文名：`心鉴`。
- 英文名：`Sym Gen`。
- 首页品牌说明：`心鉴 · 精神与心理健康科普`。
- 首页主文案：`以同理为镜，照见世间每一寸柔软`。
- 当前 Logo 使用心形结构的 SG 图案，不再使用最初的圆形字母标。
- 已删除进入网站前的独立欢迎页；现在进入网站直接看到首页。
- 首页是完整单屏 Hero，不使用旧版深色内容卡作为第一视觉。
- 首页顶部保留品牌和四个内容入口。
- 首页底部的小箭头及其动画已经确认，不应顺手重画或改速。

### 2.2 首页环境动效

当前环境动效由一个 Canvas 2D 图层实现：

- 四层柔和极光色团；
- 一条主斜向光带和两条次级光带；
- 稀疏空气粒子；
- 右下角错相呼吸圆环；
- 桌面端低幅平滑视差；
- 页面隐藏时暂停；
- 30fps；
- DPR 上限 1.5；
- `prefers-reduced-motion` 下变成静态背景。

统一动效强度由 `src/components/ambientMotion.js` 管理，当前为 `1.65`。

设计目的不是动态壁纸，也不是科技粒子背景，而是让用户在 1～2 秒内察觉页面并非静止，停留 3～5 秒后能感到缓慢呼吸。

### 2.3 纸飞机与信件

首页当前使用纸飞机，不使用信封。

纸飞机：

- 图形由项目内矢量几何绘制；
- 闲置状态约 3.8 秒一周期；
- 具有上下漂浮、小幅横移、轻微旋转、阴影与两圈扩散引导环；
- hover 时轻微抬起、放大和增强阴影；
- 点击后先平滑回正，再进入展开过程；
- 不应再次出现偶发向右跳动；
- 打开动画期间禁止重复点击。

纸飞机展开为信纸由 Remotion 帧控制，HTML 负责文字。两者不能被重新合并成图片、视频或带文字的动画。

当前时间线：

| 阶段 | 时间 | 行为 |
| --- | ---: | --- |
| `preparing` | 0.00～0.20s | 停止闲置漂浮并回正 |
| `unfolding` | 0.20～1.90s | 飞机折面展开为纸张 |
| `settling` | 1.90～2.23s | 信纸轻微落稳 |
| `holding` | 2.23～2.93s | 保持空白信纸，形成停顿 |
| `revealing` | 2.93～3.50s | 标题和正文分两级淡入 |
| `opened` | 3.50s 后 | 停留在最终阅读状态 |

当前信件内容：

> 你好，欢迎来到心鉴。
>
> 愿这里的文字，<br>
> 能陪你更从容地理解自己。
>
> 每一次认真感受，<br>
> 都是照顾自己的开始。

关闭时先淡出 HTML 文字，再反向折回纸飞机。背景遮罩进入与退出均为非线性缓动。

### 2.4 内容页面

- 桌面端保留完整左侧主导航，不能为了缩窄分类区域把主导航压到中文换行。
- 药物/疾病页面的“分类索引”可以自适应缩窄，以扩大右侧内容区。
- 小屏幕下主导航宽度、分类索引与详情比例自适应。
- 移动端列表进入详情后可以滚动，并能在返回时恢复列表位置。
- 进入具体药物详情后，滚轮不会误触发跳到下一个大分类。
- 页面内部从首页通过滚轮切换大分类时有阈值、锁定和冷却，避免一次滚动跳过多页。
- 页面之间使用等待模式：旧页面先退出，新页面再进入，避免两个页面交叠。
- 首页切出时不因侧边栏出现而突然横向位移。

### 2.5 药物详情

药物详情已经从四块静态卡调整为五个标签：

1. 适用情境；
2. 药物作用；
3. 药物动力学；
4. 药物联用；
5. 副作用。

当前约束：

- 每个标签使用符合品牌色系的独立色调；
- 不显示多余的表头左右圆形箭头；
- 仍支持点击、键盘左右键、Home/End 和移动端横向手势；
- 当前标签内容区域随文本长度增长；
- 设置合理最小高度，但不因固定高度产生内部滚轮；
- 文本宽度应跟随内容框，不能在框内无故提前换行；
- 标签名不在内容正文区域重复显示；
- “禁忌与警示”放在药物名称下方、五标签内容之前，保持足够靠上；
- “返回列表”和本地编辑操作共享紧凑工具栏，不能单独占据很高的一整行；
- 副作用数据已加入数据模型、本地编辑表单和 114 个药物词条。

### 2.6 搜索、数据和安全行为

这些行为在视觉改造期间一直要求保持：

- 搜索仍在浏览器本地执行；
- 疾病线索、相似案例、关联治疗和药物的排序逻辑保持；
- 识别直接药物名称时提供语境提示；
- 自伤、自杀、伤人、暴力、急性躯体危险和中毒等严重风险会抑制普通结果；
- warning 级提示不会错误抑制普通匹配；
- 编辑数据仍保存在 `localStorage`；
- 公开构建只读；
- 资源 URL 校验继续拒绝本地路径、私有目录、localhost、非 HTTP 协议等。

## 3. 开发历程

下面按设计和技术演进顺序记录。部分阶段存在交叉，不等同于 Git 提交顺序。

### 阶段 A：环境保护与现状审阅

最初开发约束非常严格：

- 只能操作本地仓库；
- 使用 `local-ui-redesign` 分支；
- 不在 `main` 开发；
- 不覆盖已有未提交内容；
- 禁止危险清理、强制 checkout 和 hard reset；
- 远程 push 地址曾被设为 `DISABLED`，用于避免误推送；
- 在正式授权前不 commit、不 push、不创建 PR。

随后完成了 README、数据、搜索、主入口、样式和视觉资源审阅，确认项目是单入口 React 应用，主要业务行为集中在 `src/main.jsx`、`src/data.js`、`src/search.js` 和药物数据文件中。

### 阶段 B：第一轮编辑式视觉重构

早期版本采用了更强的编辑设计：

- 固定左侧导航；
- 大号编号；
- 坐标、索引、ENTRY 等辅助英文；
- 深青色首页大卡；
- 药物、疾病、案例和资源使用明显的版面分栏；
- 页面标题使用强字重和较大的数字装饰。

这一阶段建立了今天仍保留的部分基础：

- 天青蓝、青绿、暖砂色与深青灰配色；
- 编辑式留白和明确的信息层级；
- 分类索引与详情并列；
- 内容卡弱边框、低对比背景；
- 非线性转场和 reduced-motion 基础。

但深色首页卡、巨大 SG 装饰、坐标式标签和过多英文装饰后来被逐步替换。

### 阶段 C：页面转场修复

转场曾出现两个明显问题：

1. 新页面已经出现，旧页面尚未完全退出；
2. 首页 `Sym Gen` 的字距动画在中途停顿或跳变。

处理结果：

- 创建并完善 `AnimatedPresence`；
- 页面级切换改为 `mode="wait"`；
- 退出层设置 `aria-hidden` 和 `inert`，避免透明旧层继续拦截点击；
- 对页面、详情、弹窗和 toast 使用不同时间参数；
- 页面切换方向根据导航顺序、详情开合和滚轮方向计算；
- 统一使用非线性 cubic-bezier；
- 标题字距和透明度动画避免临界帧突变；
- 修复线上新版看得见但完全点不了的问题，根因是退出层仍覆盖在交互区域。

### 阶段 D：字体、装饰文字与案例页性能

曾进行以下调整：

- 正文改为更接近 Noto / Source Han 的中文字体栈；
- 标题继续使用较硬朗的无衬线展示字体；
- 药物详情中的 `ENTRY` 一度改为药物英文名，并支持长英文分行与右对齐；
- 后续又删除了药物详情的大号英文水印，减少视觉干扰；
- 首页 `SG`、`OPEN` 等缺乏内容关系的装饰字被删除或改为有语义的项目文字；
- 案例页面切换中的卡顿通过减少昂贵布局、调整 presence 时间和移动端滚动处理改善。

### 阶段 E：首页从“内容卡”变为完整 Hero

首页经过一次较大的方向调整：

- 不再将内容放进深色大卡；
- 改为全视口青蓝—青绿—暖黄渐变；
- 品牌移到左上，栏目入口移到右上；
- 主标题、说明、搜索和互动对象组成一个整体视觉群；
- 搜索框改为更宽、更轻、更适合自然语言输入；
- 主视觉群多次调整左右比例，最终保持略偏左而非严格几何居中；
- 删除顶部或底部缺乏意义的坐标和状态文字；
- 删除首页之前的独立欢迎页；
- 替换品牌 Logo；
- 更新首页主文案。

这一过程中尤其确认：不同屏幕下应保持“视觉居中”，不能只用固定像素实现数学居中。

### 阶段 F：侧栏、分类索引和响应式布局

曾经出现过一个误解：为了让详情区域更宽，把最左侧主导航也压窄，导致“疾病科普”“案例分析”等中文换行。

最终规则是：

- 最左侧主导航保持可读，不随意压成窄图标栏；
- 要缩的是内容区里的“分类索引”；
- 右侧详情应获得更高比例；
- 小屏幕下主导航转为抽屉；
- 移动端详情进入后必须允许纵向滚动；
- 详情返回后恢复列表滚动位置；
- 侧栏、分类索引和详情比例分别响应屏幕宽度，而不是共用一个固定宽度。

### 阶段 G：药物五标签与副作用

合作者在数据侧增加“副作用”方向后，前端完成：

- `sideEffects` 字段；
- 通用药理分类默认副作用；
- 部分药物专属覆盖；
- 本地编辑表单；
- 第五个标签；
- clay 暖灰粉色调；
- 可变高度内容；
- 重要警示前置；
- 表头箭头删除；
- 标签键盘与触屏操作；
- 文本宽度和换行修复。

需要注意：副作用内容属于面向公众的摘要，仍需专业内容审校，不能被 AI 当作完整药品说明书。

### 阶段 H：信封实验

纸飞机设计不稳定时，曾短暂改为信封：

- 极简矩形；
- 上方倒挂三角形翻盖；
- 点击打开、弹出信纸；
- 背景变暗；
- 关闭时反向收起。

这个方向被后续明确取消，原因包括：

- 信封图形多次看起来像色块拼接；
- 图形位置与首页文字群不协调；
- 下方斜线和多块纸面让信封不自然；
- 互动气质不如纸飞机轻盈。

仓库历史工作区曾产生信封组件、预览 SVG、生成脚本和 JSON。这些不属于当前运行路径，不应重新接入，除非合作者明确推翻现有纸飞机方向。

### 阶段 I：纸飞机 SVG、CSS 和 Lottie 探索

纸飞机先后尝试：

- polygon 拼接；
- 固定坐标内联 SVG；
- CSS 分片折叠；
- 程序生成 Lottie JSON；
- 将动画与 HTML 文案分离。

其中一些方案被放弃：

- polygon 视觉不够精致；
- CSS 折叠停顿点多，容易穿插；
- Lottie 方案增加生成脚本和维护成本，未成为最终实现；
- “飞机消失、信纸突然出现”不符合“同一张纸展开”的要求。

最终采用：

- React + Remotion 控制折面和信纸帧；
- Web Animations API 控制外层闲置漂浮；
- HTML 控制标题、正文、落款和关闭按钮；
- 明确状态机与空白停顿；
- 背景遮罩和键盘交互继续由 React 控制。

### 阶段 J：首页光效多次重做

光效经历了多次反馈：

1. 静态白色斑点，几乎看不出呼吸；
2. CSS blur 与渐变移动，变化过弱；
3. 过多透明几何图形，画面杂乱，被整体撤回；
4. 圆环、十字和装饰图形实验，其中十字被明确删除；
5. 光束发生弯曲或像曲线，视觉不稳定；
6. Canvas 版本将光团、直线光带、粒子和圆环统一起来；
7. 第三轮用统一强度参数将运动提高到可感知范围。

当前版本的原则：

- 光带必须保持直线；
- 光斑呼吸与光带位移应错相；
- 粒子少而可见；
- 右下圆环清楚但不能抢过纸飞机；
- 不把画面做成霓虹、科技、宇宙或游戏界面；
- 静态截图仍应清爽；
- 运动只改变 transform、opacity 和 Canvas 绘制参数，不逐帧动画 CSS blur。

### 阶段 K：部署与线上问题

部署过程中出现过：

- GitHub Pages 仍显示旧版；
- 新版上线后所有内容无法点击；
- 贡献者列表未及时出现当前开发者。

对应处理：

- Vite 构建使用相对 base；
- GitHub Actions 在 PR 中执行数据、测试和构建验证；
- 只有 `main` push 或手动工作流部署 GitHub Pages；
- 修复透明退出层拦截点击；
- Git 提交作者使用与 GitHub 账号绑定的 noreply 邮箱。

2026-07-31 的整合已将当前重设计、main 的数据与工程能力，以及 Mauris Chueng（Chen）的纸飞机空闲轨迹优化汇入同一合并历史。正式 Pages 仍只由 `main` 的部署工作流发布；分支预览与正式站点始终是两件事。

## 4. 明确放弃、删除或不应自动恢复的方向

后续 AI 在准备实施下表中的方向时，必须先告知合作者：

> “这个方向在此前开发中被明确否定、删除或替换过，原因是……。你是否确定要覆盖已有决策并继续？”

只有收到明确确认后才能继续。

| 方向 | 状态 | 原因/替代方案 |
| --- | --- | --- |
| 恢复独立欢迎页 | 明确删除 | 用户希望打开网站直接进入首页 |
| 用信封替代纸飞机 | 明确取消 | 图形笨重、位置不协调；当前使用纸飞机 |
| 修改已确认的纸飞机轮廓 | 需先确认 | 当前造型和展开逻辑已经过多轮验证 |
| 删除信纸展开后的空白停顿 | 明确否定 | 停顿用于仪式感，不是卡顿 |
| 打字机式逐字出现 | 明确否定 | 当前采用两级淡入 |
| 修改底部小箭头 | 明确要求不动 | 除非出现实际 bug |
| 首页加入十字、加号 | 明确删除 | 与心理健康科普气质不协调 |
| 大量透明几何图形铺满背景 | 已做后撤回 | 画面杂乱、失去留白 |
| 让光束弯曲、摆动成曲线 | 明确否定 | 当前光束必须保持直线 |
| 只用两个静态白斑做“光晕” | 明确否定 | 必须有可感知的呼吸与位移 |
| 霓虹、星空、科技粒子风 | 明确禁止 | 当前目标是清爽、温和、专业 |
| 把最左主导航压到中文换行 | 明确否定 | 应缩窄分类索引，而不是破坏主导航 |
| 恢复药物标签表头左右箭头 | 明确删除 | 标签已可点击、键盘和滑动操作 |
| 在药物内容框内重复当前标签名 | 明确删除 | 标签头已经表达所属栏目 |
| 把禁忌与警示放在所有长内容之后 | 明确否定 | 重要内容应靠近药物名称 |
| 固定药物内容框高度并内部滚动 | 明确否定 | 内容框应按文本高度展开 |
| 详情阅读时滚轮跳到下一个大栏目 | 明确否定 | 会打断阅读 |
| 新旧页面同步叠在一起转场 | 明确否定 | 使用等待式 presence |
| 使用线性动画 | 明确否定 | 根据动作使用非线性缓动 |
| 使用 emoji 或普通发送图标替代纸飞机 | 明确禁止 | 破坏当前折纸气质 |
| 引入 Three.js、GSAP 等重型依赖 | 当前明确不需要 | Canvas + Remotion + Web Animations 已足够 |
| 将文字做进动画文件 | 明确否定 | 信件文字必须是可访问的 HTML |
| 上传原始 PDF、OCR 或内部资料 | 永久禁止 | 隐私与版权边界 |

## 7. 后续 AI 必须遵循的设计风格

### 7.1 情绪目标

界面应让人感到：

- 安静；
- 被理解；
- 可信；
- 柔和但不幼稚；
- 有生命力但不兴奋；
- 专业但不冰冷；
- 精致但不过度装饰。

这是心理健康公益知识库，不是效率工具后台、医疗器械面板、潮流品牌海报或科幻产品。

### 7.2 视觉语言

建议关键词：

- 清透；
- 空气感；
- 轻编辑设计；
- 大面积留白；
- 柔和低饱和渐变；
- 稀疏的圆环与弧线；
- 低频呼吸；
- 非对称但稳定的构图；
- 温柔的纸张和折纸触感；
- 内容优先的层级。

图形点缀应像空气中的光、纸面上的压痕或水面扩散，而不是图标贴纸。

### 7.3 品牌色

主色：

- 天青蓝 `#8FD1E1`；
- 暖砂色 `#E8C99B`；
- 薄荷青绿 `#A8D4C5`；
- 暖白；
- 深青灰文字。

辅助环境色：

- cyan `#7ED6DF`；
- green `#8FDAC2`；
- warm `#F2D597`；
- gray pink `#E7C5CD`。

不要：

- 高饱和纯蓝或纯橙；
- 纯黑粗边；
- 强紫色霓虹；
- 大面积荧光；
- 过强玻璃拟态；
- 塑料高光。

### 7.4 字体

- 中文 UI 优先：`Noto Sans SC` / `Source Han Sans SC`；
- 标题使用稳重的无衬线展示字；
- 正文应有足够行高，避免“塑料感”和过度压缩；
- 英文与数字可使用较克制的几何无衬线或 mono 作为辅助；
- 辅助英文必须有语义，不能只为“看起来高级”而添加。

### 7.5 动画

- 禁止线性匀速；
- 使用符合物体行为的 cubic-bezier；
- 页面切换先退出后进入；
- 同一动作最多两级错峰，不做逐行蹦出；
- 不使用弹跳、橡皮筋或明显过冲；
- 背景运动低频、错相；
- hover 反馈短而克制；
- reduced-motion 必须保持完整功能；
- 动画期间防重复触发；
- 组件卸载清理定时器、Animation、监听器和观察器。

### 7.6 响应式

- 设计不能只在 1920px 成立；
- 同时检查 1366、1024、768、390px；
- 使用 `clamp()`、网格比例、内容最小宽度和安全区；
- 不用固定像素强行居中；
- 移动端优先保证可滚动、可返回和不遮挡；
- 内容详情不能因为顶部工具栏被挤出窗口；
- 长文本必须自然扩展。

## 8. AI 协作协议

合作者可将本节直接作为后续 AI 的前置指令。

### 8.1 开始修改前

AI 必须：

1. 阅读本文件；
2. 检查当前分支和工作区；
3. 阅读将修改组件的实际代码；
4. 区分“当前运行路径”和“历史实验文件”；
5. 列出功能不变量；
6. 确认是否会触碰已明确否定的方向；
7. 在修改前说明本轮范围。

### 8.2 遇到历史冲突时

如果新要求可能恢复此前否定、删除或替换的方案，AI 不得静默执行。它必须明确说明：

- 哪个历史决策会被覆盖；
- 当时为什么删除或替换；
- 当前实现是什么；
- 继续会影响哪些组件、状态或响应式规则；
- 询问合作者是否确认覆盖。

示例：

> “你提出恢复信封，但此前信封方案因图形笨重和首页构图不协调被明确取消，当前已确认的是纸飞机和同纸展开逻辑。你是否确定要推翻该决策？如果确定，我会先保留当前实现并单独做可回退实验。”

### 8.3 修改边界

视觉任务默认不授权：

- 改搜索排序；
- 改风险判断；
- 改数据字段语义；
- 改 localStorage；
- 删除数据；
- 上传内部资料；
- 改部署目标；
- 合并分支。

如果确实需要，AI 应先说明原因和风险。

### 8.4 实施原则

- 小步修改，优先复用现有组件；
- 不为一个效果同时引入两套动画系统；
- 先完成静态构图，再做动画；
- 先处理布局，再处理点缀；
- 不用动画掩盖图形本身的问题；
- 不通过堆透明度弥补运动轨迹不清楚；
- 不通过增加大量粒子弥补层次不足；
- 不把被删掉的历史代码重新 import；
- 不随意改动已确认的文案。

### 8.5 验证要求

至少运行：

```bash
npm run verify
```

视觉改动还应：

- 在真实浏览器观察至少 5 秒；
- 检查 1920、1366、768、390px；
- 检查控制台；
- 检查页面新旧层是否交叠；
- 检查移动端滚动；
- 检查键盘焦点；
- 检查 reduced-motion；
- 若涉及纸飞机，完整测试打开、停顿、显字、关闭和重复点击。

## 9. Git 与协作建议

- 日常开发继续使用功能分支，不直接在 `main` 修改；

推荐提交拆分：

1. 功能与数据；

## 11. 最终提醒

这个项目的设计价值不在于“效果多”，而在于：

- 内容复杂但阅读压力低；
- 运动可感知但不打扰；
- 视觉温柔但不失专业；
- 互动精致但功能保持直接；
- 对心理健康内容保持克制和尊重。

后续任何 AI 如果试图用更多装饰、更重依赖或更强动画换取“高级感”，应先停下来检查：它是否仍在帮助读者理解内容、保持情绪安全和完成任务。
