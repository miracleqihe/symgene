# 本地数据说明

本地编辑能力只在开发模式开放。公开生产版本是只读界面。存储层保留导入、导出、恢复和重置接口，但当前重设计界面没有呈现旧版数据管理面板；后续若重新提供入口，应直接调用现有接口，不能绕过迁移、验证和备份流程。

## 主数据与版本

主键为：

```text
symgene-wiki-data-v1
```

键名为兼容旧安装保持不变，值已经升级为存储信封：

```json
{
  "schemaVersion": 4,
  "seedVersion": 13,
  "savedAt": "2026-07-29T12:00:00.000Z",
  "data": {
    "drugs": [],
    "disorders": [],
    "cases": [],
    "resources": []
  },
  "deletedIds": {
    "drugs": [],
    "disorders": [],
    "cases": [],
    "resources": []
  },
  "localOverrides": {
    "drugs": {},
    "disorders": {},
    "cases": {},
    "resources": {}
  },
  "seedIds": {
    "drugs": [],
    "disorders": [],
    "cases": [],
    "resources": []
  }
}
```

`schemaVersion` 表示存储结构，`seedVersion` 表示项目内置内容版本。两者不能混用。`seedVersion` 必须是非负整数，`0` 是合法的历史版本；新建信封未提供该字段时使用当前版本，但已经存在的信封若保存为 `null`、缺失、负数或非整数，会被验证和修改操作拒绝，不能静默升级。`deletedIds` 记录用户明确删除的内置条目，防止后续来源合并将其恢复。`localOverrides` 按集合和 ID 记录开发模式编辑器实际修改过的内置字段；`seedIds` 按集合记录上一次读取时的内置 ID，用于区分后来从代码删除的内置条目和用户自行新增的条目。

## 迁移与合并顺序

读取旧 `meta.version` 格式或较早信封时，流程为：

1. 读取并保留原始字符串；
2. 在项目自己的备份键下创建逐字备份；
3. 解析旧格式并建立当前信封；
4. 以四类代码数据为基线，回放明确记录的本地字段覆盖；
5. 运行与正式数据相同的完整性验证；
6. 仅在验证通过后写回主键。

`handbookDrugs` 以及 `data.js` 汇总的疾病、案例和资源都是各自内置集合的内容来源。代码中增加、修改或删除字段或条目时，浏览器会在下次读取种子时自动同步；开发服务器热更新时，`seedRevision` 会让当前页面立即重新读取并合并。普通文案变更不需要逐字段迁移白名单，也不要求只为触发同步而提升 `seedVersion`。

开发模式编辑器保存内置词条时，只把实际发生变化的字段记为本地覆盖；同一词条的其他字段继续跟随代码。字段恢复成当前代码值后会自动清除覆盖标记。用户新增的条目继续保留，用户明确删除的内置条目继续由 `deletedIds` 保护。若代码删除的疾病仍被本地自定义案例引用，合并器会暂时保留该疾病，直到案例被删除或改绑，以维持交叉引用完整性。

schema v3 只记录了药物字段来源。首次升级到 schema v4 时，药物覆盖记录会完整迁移；疾病、案例和资源中与当前代码同 ID 的旧快照以当前代码为准，升级写回前会自动保留旧主值的逐字备份。schema v2 和旧 `meta.version` 格式没有字段级来源记录，同 ID 内置内容同样以当前代码为准；不存在于当前代码中的本地条目会保留为自定义内容。

旧格式的来源信息并不完整，因此首次升级存在两个明确边界：旧格式中曾删除但没有 tombstone 的内置条目可能重新出现；在首次 schema v4 迁移前就已从代码删除、同时仍存在于疾病/案例/资源旧快照中的条目，会按自定义内容保留，因为无法可靠区分它与真实的本地新增。迁移优先避免误删用户数据。完成 schema v4 写入后，后续代码字段和条目的增删改都能根据 `seedIds` 与 `localOverrides` 稳定同步。

## 删除依赖保护

疾病仍有关联案例时不能直接删除。必须先删除关联案例，或把案例改绑到其他疾病，再删除该疾病。操作层和开发模式界面都会执行这项检查，以防疾病删除静默级联造成种子案例或自定义案例丢失。

## 自动备份

自动备份键以 `symgene-wiki-backup-` 开头，最多保留最近 5 份。清理仅匹配该前缀，不删除主数据或其他应用的本地存储。

以下操作会在写入前备份当前值：

- 自动迁移写回；
- 导入备份；
- 恢复项目默认数据。

恢复自动备份采用更严格的顺序：先读取、解析、迁移并完整验证目标备份；验证成功后才创建当前状态的恢复前备份，最后写入目标。无效目标不会改变主数据或备份列表，也不会新增备份或淘汰最旧备份。当前状态备份创建失败时不会写入恢复目标。

存储接口可以提供备份时间、结构版本、种子版本、大小和原始内容。当前界面尚未暴露这些管理操作；无论未来采用何种界面，无效备份都不能恢复。

## 导出与导入

导出文件名形如 `symgene-backup-2026-07-29.json`，MIME 类型为 JSON。文件包含：

- 固定格式标识 `symgene-local-backup`；
- 结构和种子版本；
- 导出时间；
- 四类实际数据；
- 删除记录；
- 四类内置词条的字段覆盖与来源 ID 记录。

导出不包含搜索描述、浏览器信息、日志或用户身份信息，也不会发送网络请求。

导入文件上限为 5 MB。程序实际读取并解析 JSON，不只检查扩展名。导入会验证格式标识、版本、重复 ID、必填字段、交叉引用、资源 URL 和本地路径；未来版本与无效文件会被拒绝。确认界面只显示数量、增加/覆盖数量、删除记录数量和版本，不显示全部内容。

导入文本只作为数据处理和普通 React 文本展示，不执行 HTML、脚本或模块，也不会自动访问其中的 URL。用户取消确认时不会写入。

## 恢复默认数据

恢复默认数据会先备份当前状态，然后恢复当前种子并清空删除记录。它不会删除其他应用的 `localStorage` 键。该操作会从当前状态移除用户新增和修改内容，因此必须先确认。

清除浏览器站点数据会同时删除主数据和自动备份。如需保留本地编辑内容，请先导出备份。

## 隐私边界

浏览器本地存储不是安全加密存储。请勿录入真实患者姓名、联系方式、地址、病历号或任何可以识别个人身份的信息。仓库、测试夹具和问题报告同样不得包含真实患者资料、原始书籍内容、OCR 文本或私人文件路径。
