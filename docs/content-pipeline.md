# 知识内容与教学材料

网站的运行内容统一从 `src/content/knowledge.json` 读取。原先五个组装模块已收敛到这一份内容包，条目、顺序及人工文字保持一致；历史存储迁移需要的一段旧数据留在测试夹具中。

`src/content/reading.js` 提供公众阅读引导、常见疑问、明确虚构的教学情景、延伸阅读和教学 Prompt。`KnowledgeReading` 复用这些资料，按现有 `relatedDrugIds`、`disorderId` 建立实际导航。它不改变症状搜索、排序、风险规则或本地存储。

公众页面不显示取材状态、候选证据、审校工作流或覆盖率，也不在每个正文段落后显示书名、页码或说明书链接。适用地区等影响理解的条件仍写在相关正文中；公开链接集中在页末延伸阅读。完整逐点来源位置保存在内容包内部，公开教学材料只带可访问的公开参考，不披露私有教材目录与提取位置。团队取材工具与公众阅读界面独立运行，原书材料只保存在本机内容管线中。

药物的五个标签、禁忌与警示、特殊人群和监测使用同一分点组件。换行定义一个语义点；组件清除已有的列表标记，不改写原句、数值或负号。正文可以自然增长，不引入固定高度的药物面板。

## 生成与使用

`npm run build:teaching` 从同一内容包生成 358 个词条 Markdown、对应 Prompt、带 SHA-256 的目录及 `llms.txt`。`npm run build` 自动先执行此步骤。页面 head 披露相对路径，兼容部署在子目录的静态网站。

下载的词条 Markdown 与网站使用同一正文选择函数和分点规则。教学 Prompt 包含当前显示正文、问题与可访问的公开参考。手写内容和浏览器自行修改的字段不会因此继承未经核实的来源。Prompt 要求实际核对来源，不能声称读取了无法访问的材料。公开带读 Skill 位于 `public/skills/mental-health-reading/SKILL.md`。这些入口无需模型 API、账户或侧边 Agent 服务。

重新生成时应检查整个目录与 manifest 对应，撤回词条须同时撤回其 Markdown、Prompt 和索引记录。新增或删除内容后先重新生成，再运行完整验证；不得保留悬空材料。

`src/content/communication.js` 为公众表达与教学带读提供共用准则；生成器把同一准则写入每个词条的 Prompt 和公开 Skill，避免两处逐渐分叉。准则借鉴案例书第一章“晤谈的程序”“沟通技巧”中的倾听、开放式询问、复述核对和中性用语；用于文字科普时还增加了自主选择、隐私及 AI 身份要求。不会照搬临床问诊、身体接触、身份称呼或仅凭用词推断性格的做法。原书定位和采用范围只保存在本机取材记录。

用户提供的案例书 OCR 清洁稿在独立管线内按原有页标记建立不可变索引，保留文件哈希、行号、PDF 页序及尚未核验的印刷页候选值，不重新进行全书 OCR。主题提及只生成编辑取材线索；目录命中、题目数量和相似症状都不登记为已完成案例。改写前需连同前后页、提问及解题思路核读，核实 OCR 中的药名、单位和人物关系。公众情景独立虚构，不公开复制原书病历，也不据案例为用户匹配诊断或选药。

## 全局与分模块 Agent 指南

`src/content/agentGuide.js` 复用 `communication.js` 的倾听准则与 `regions.js` 的中国适用要求，统一首页、六个模块、358 个词条 Prompt 和科普带读 Skill。首页提供“全局 Agent · 一起读懂”，各模块页提供“AI 讲解指南”；这些入口展示、复制和下载文本，不调用外部模型。

公开规范不带私有教材目录、书籍元数据、原书页码或实施方案附录说明。六类模块分别约束药物解释、疾病理解、虚构案例讨论、资源核验、研究解读及图表与机构地图阅读。普通知识问题允许直接回答，个人经历允许跳过；一次一问不构成安全风险下的追问上限。明确风险表达先澄清即时性，入口核验不能延误现实求助。

生成器同源输出 `public/agent/global.md`、`public/agent/modules/*.md`、带 SHA-256 的 `public/agent/manifest.json` 和 Skill。`index.html` 与 `llms.txt` 披露入口，使用相对路径兼容子目录部署。生成文件不作为独立手工维护副本。

指南可复制到用户常用的 LLM 聊天中独立使用，支持倾听困扰、疾病与治疗的一般信息、情绪支持和就医准备；不以打开网站、选择模块或联网为前置条件。主题材料与心鉴均为可选参考，模块不会锁定后续话题。Prompt 不会赋予模型诊疗资质、数据库连接或跨会话记忆，也不保证任意平台的执行效果；未进行跨模型效果测评。

## 取材管线的交付边界

独立内容仓库负责 EPUB、PDF 文字层和 Markdown 的本机提取；网页仓库消费公开内容包，不读取原书或 SQLite 索引。候选资料命中只用于编辑工作，不证明药物主张正确或资料完整。

`src/content/drugProfiles.json` 只收录已完成当前资料复核的专业补充；`professionalFor()` 在详情和生成材料时使用它，保留原始内容包及浏览器实际修改的字段。每篇包含八个专业字段，每个字段对应来源与位置。复核记录属于本地编辑材料，AI复核不等于临床专家签署。

已有手写长文使用 `amendments` 做定向修订，不整栏覆盖。每项记录字段、原文唯一片段 `originalText`、修订理由及带逐点来源的 `replacement`；原稿仍保存在原始内容包中。原文不存在、出现多次、目标互相重叠或同一栏同时整栏替换时，生成器必须失败；纯删除也必须保存理由与依据。完整生成前先检查全部补充，防止校验失败后留下部分新文件。

未改动的手写点只在确实复核后通过 `retainedEvidence` 单独登记来源，不借用相邻修订的证据。局部来源只对应实际核对的完整语义点，不据一个有来源的短语认定整段已核实。教学 Prompt 用栏名和完整显示正文的点序列出这些点实际对应的公开来源位置，不附私有教材位置，不为整栏统加引用。浏览器中实际修改或明确清空的字段优先保留，不应用该栏修订，也不继承修订来源；这些来源记录和修订理由不显示为公众页面的工作流标签。

`src/content/caseProfiles.json` 使用相同的补充与来源接口，`caseFor()` 仅在案例详情和教学材料中应用补充，不改原始案例、搜索权重或排序。数组内容按值与原稿比较，未改过的数组可得到补充，实际修改或明确清空的字段保留用户内容且不继承补充来源。案例的“陪伴者可以怎样开口”与“一起想想”供带读与沟通练习，不能作为自测、诊断或选药流程。

`src/content/disorderProfiles.json` 与 `disorders.js` 为疾病十栏正文提供同样的接口；页面、Markdown 和 Prompt 均通过 `disorderFor()` 选择内容。`summary`、`details` 保留字符串，其余八栏按换行保存语义点、显示为数组。原始词条及关联药物不变，本地实际修改或清空的字段优先且不继承补充来源。来源记录按字段和语义点保留，公开材料仅附公开可访问的参考。

`npm run audit:knowledge-coverage` 将三库检查写入被忽略的 `work/content-review/knowledge-coverage.json`。疾病逐点来源中须实际采用带原文件 SHA-256 的 EPUB，案例须实际采用带摘要的案例书来源、明确虚构身份；两库均检查实际采用的中国大陆参考。仅把书列入来源表不算采用。`-- --require-complete` 要求三库全部条目的结构及药物地区记录通过，适合最终覆盖检查；这仍不证明主张正确、读完所有相关章节或已完成医学与语言审读，须另查实际编辑记录。检查结果不进入公众页面。

新药物补充除字段来源外还在内部保留逐点证据范围，区分本药资料、类别背景、科普解释和沟通教学改写。`npm run audit:drug-coverage` 把八项字段与逐点对应的结构检查写到本机编辑目录；加 `-- --require-complete` 时，缺项会以失败退出。结构检查不代替医学和公众表达复核，不把四个标题或一定字数当作完成。

来源筛选同时核对药物专属行、类别章节、特殊人群和警示。手册转换稿中存在表格共列、断字和数字识别问题，时间表格单位不明确时不发布猜测的数字；外部用途还须核对地区、剂型、具体产品与来源日期。新增阅读辅助与八个非空字段都不证明药物资料已经全面。全药物逐条补充、主张证据对应及案例书定向取材仍需逐项完成，不能把索引建立或候选命中登记成正文已完成。

## 中国大陆受众的资料依据

国内批准用途、剂型、适用年龄和禁忌先核对中国具体产品的说明书及药监部门修订要求；疾病评估与治疗原则优先查国家卫生健康委规范及国内专业指南。国内指南讨论的治疗方式不自动成为获批适应证，中文翻译的国外教材也不是中国说明书。美国、英国等地区的资料保留为补充，并在相应结论旁说明地区和产品差异。没有取得中国批准依据时，不推断已获批或未获批，不把搜索未命中等同于未上市。

`regions.js` 是全站教学 Prompt 与公开 Skill 的共用地区规则。国内阅读链接优先，专业说明书只标其真实语言；访问日期不写成说明书修订日期。国内通用查询入口只用于查找具体产品，不充当每篇医学主张的证据。国家规范按实际版本标注年份，未取得新版全文时不声称采用新版推荐。

药物补充的 `regionalReview` 保存受众、核对日期、国内产品来源、对照来源和具体限制。中国产品来源还需 `kind: label`、地区、语言、修订及访问日期，以及 `product` 中的成分名、剂型、规格、上市许可持有人和批准标识。`audit:drug-coverage` 分别统计地区记录完整度与取得中国具体产品依据的条目数；国外资料或未知状态不会计入中国产品核验数。`--require-complete` 同时要求正文逐点结构与地区记录完整；这个检查不证明医学正确，也不替代内容审查。地区核对状态只保存在编辑报告中，公众页不增加状态标签。
