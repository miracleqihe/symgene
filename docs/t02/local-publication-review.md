# 当前内容公开前的审读准备

`check:publication` 仍固定返回 `LEGACY_PUBLICATION_APPROVAL_NOT_BOUND`。它没有读取可信审批记录的放行分支，因此不能把“收到项目负责人同意”或“填完模板”当成工程门禁已解除。后续须在独立 topic → dev PR 中实现并审核认证审批与实际输出的绑定；不能在晋级 PR 塞修复，不能取消生产检查。

## 现在可以执行的准备

使用 Node 22、锁文件及干净的已提交工作树，先 `npm ci`、`npm run verify`，再运行：

```text
node scripts/local-content/export-publication-review.mjs --output <新的Git外审读目录>
```

导出器从干净提交重新执行受限审读构建，避免旧 dist 冒充新提交的产物；不执行 release 或公开操作。它核对锁定源文件、教学材料目录、正文与 Prompt 的独立摘要、全局/模块指南和 Skill，以及 public 与 dist 字节一致性。实际 HTML、JS 及其余构建文件一并列入输出摘要，并复制到 Git 外审读目录。额外生成未索引材料、内容漂移、目录穿越、符号链接、仓库内目标或既存目标均拒绝；不读原书、患者资料、索引数据库或凭据。

登记底稿为当前版本重新生成，列出全部词条、资源和指南。负责人、医学/公众表达/权利决定均为 null。旧审读模板所指历史版本不能静默升为当前批准，原模板和人工记录保留。审读包本身及哈希没有认证效力，也不接入生产放行。

## 需要真实决定的事项

- 医学：指定具备适当专业能力的审读者，审查重要结论、中国适用性、特殊人群与风险，以及案例/Prompt 会否诱导自诊或自行选药。
- 公众表达：由项目负责人或指定中文编辑审查可读性、尊重与倾听方式、误解风险，保留逐项修改或有条件结论。
- 权利与隐私：对实际来源、改写/引用、展示与再发布范围、素材许可和数据最小化留依据。持有原书文件、网页可访问或有 GitHub 写权限均不能由程序推为许可。
- 每项决定需绑定精确内容/输出摘要、身份与职责依据、范围、证据、时间和有效期。真实凭据与私有证据不进入公开 PR；可信身份的登记和校验方案须单独审查。

地区结构检查通过不代表中国具体产品依据齐全。导出器逐项列出尚未达到 `cn_product_verified` 元数据条件的药物；该状态通过也不等于独立药监或医学核验。不把通用查询入口当成具体产品说明书，不据搜索缺失推断国内上市状态。

## 与 T02 正式采用分别判断

当前晋级的直接自动阻断是公开审批；晋级本身还须独立 PR 审核、对实际集成点的检查和用户后续 main 授权。T01.2、A16/B8 具体输入、G2 两报告、G3 四维审核、G4 目标环境和 G5 接管是正式 T02 真实处理/采用的前置；保持实验开关和 legacy 边界时，不把这些待办写成每个词条必须新增的一组 CI 失败。

两个 Vite 消费者并发启动曾超时，根因未确认；当前仍只接受顺序演练，不声称并发可靠性已通过。大 chunk 警告和未测浏览器边界是已知限制，不是已经发现的新增直接发布故障。
