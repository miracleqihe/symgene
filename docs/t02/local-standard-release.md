# 现有网站的正常发布流程

2026-10-23，项目负责人明确要求“不需要这些阻断”：撤销此前为legacy网站额外引入的医学、公众表达、来源使用前置审读阻断，以及依赖尚未实现的认证审批路径的固定失败检查。此决定调整发布策略，不生成或补签任何医学审核记录。

现有网站、词条、Markdown、Prompt和Skill按主题分支→dev→main的正常工程流程更新。继续要求CI、既有代码审核、Code Owner及晋级来源检查；不要求为全部既有内容取得三类逐项签署后才能合并。公众表达和来源使用由项目负责人负责，医学审读暂缺，记录如实保留，不能宣称已获医学批准。

`check:publication`保留为兼容命令，只验证固定内容字节、校验器和legacy采用隔离；有效内容返回`LEGACY_RELEASE_INTEGRITY_VERIFIED`，失配真实失败。环境变量、伪造模板和approved字段既不能替代完整性验证，也不会产生医学批准。CI中的对应检查改名为`Publication integrity`。main分支保护移除额外的`Publication approval`，保留原规定的工程检查和人工代码审核。

`build:release`可以正常生成有效legacy站点。正常构建中的数据、链接、测试、私有路径检查、生产只读、搜索和存储保护均保持。原书、全文、抽取中间件和私有数据仍不提交。

本次不启用新的T02签名内容包生产采用，不把G2–G5记录为通过，不制造人员身份或审读结果。历史说明中的“固定BLOCKED”“三类签署作为legacy发布前提”由本决定替代；历史测试记录保留为当时的实际结果。

尚未合并的安全PR若仍固定返回`PUBLICATION_AUTHORITY_NOT_CONFIGURED`，其涉及legacy网站的审批条件也应按本决定同步调整。提交身份、可信CI、main来源、精确制品绑定等工程校验可以保留，不能重新引入被撤销的内容审读前置条件。调整应在主题PR完成，不向晋级PR夹带修复。
