# 前端架构

## 应用入口与组合

`src/main.jsx` 是当前单入口应用，组合首页、四类目录、详情、搜索和开发模式编辑器，并维护导航、当前词条与页面转场状态。视觉与动画拆分在 `src/components/`，全局样式入口为 `src/styles.css`。

主要职责分布：

- `src/main.jsx`：页面组合、导航、搜索展示、列表与详情、开发模式编辑；
- `src/components/`：等待式页面切换、药物五栏、首页环境动效、标题与纸飞机信件；
- `src/styles/`：设计变量、布局、组件外观与非线性动效；
- `src/hooks/useLocalKnowledge.js`：当前 React 界面与本地存储层的边界；
- `src/storage/`：迁移、校验边界、备份、导入、导出和重置。

应用入口不直接读写原始 `localStorage` 值，也不实现迁移或文件解析。编辑器只提交结构化词条，最终写入由存储 hook 和存储层完成。此前用于进入网站的独立欢迎页已按产品决策删除，不应在结构重整时自动恢复。

## 数据模块

正式种子由 `src/data.js` 汇总药物、疾病、案例和资源模块。`cloneSeed()` 为运行时和验证脚本提供隔离副本。数据验证器位于 `src/validation/dataValidation.js`，命令行入口为 `scripts/validate-data.mjs`。

疾病、药物、案例、风险词、搜索扩展与评分属于医学或医学相关内容。修改这些内容时必须进行单独的内容审核，不能把工程重构当作内容变更的授权。

## 搜索与风险提示数据流

首页把原始描述和当前知识数据传给 `matchKnowledge()`：

1. 原始查询用于分词和风险识别；
2. 风险识别先按标点和转折连接词拆成独立事件，再分别判断主体、否定、时间、假设语境和当前行动证据；
3. 每个事件独立分级，整句采用最高风险级别，避免一个被否定的片段掩盖同句中已经发生的吞药、伤人或急性身体危险；
4. 规范化文本用于空查询判断和不区分大小写的比较；
5. 疾病按既有字段权重和概念扩展评分；
6. 案例只在关联疾病命中时参与排序；
7. 关联药物作为后续资料呈现，不作为首要搜索结果；
8. `critical` 风险会抑制普通疾病、案例和药物结果。

风险输出分为 `critical`、`warning` 和 `guidance`：已经实施、正在发生、当前计划、持有明确手段或急性身体危险进入 `critical`；需要确认当前性或行动状态的本人风险进入 `warning`；第三人称、假设以及已结束且当前安全的语境进入 `guidance`。明确否定只排除所在事件，不能覆盖其它独立风险事件。

搜索和风险识别只在浏览器内运行，不等于诊断，也没有训练模型参与决策。当前实现是可审计的有限规则，仍不能可靠处理所有隐喻、反讽、长距离指代、拼写变化或信息缺失；`warning` 只表示需要进一步确认，不能替代专业安全评估。

## 存储边界

`useLocalKnowledge()` 是 React 与存储层之间的接口。存储实现位于：

- `constants.js`：主键、版本和备份上限；
- `migrations.js`：信封格式、旧格式兼容、种子合并和 tombstone；
- `operations.js`：词条新增、修改和删除；
- `storage.js`：读写、迁移前备份、恢复和重置；
- `importExport.js`：5 MB 文件限制、导出格式、导入解析与摘要。

schema v4 对药物、疾病、案例和资源使用同一套来源合并器：代码数据是内置基线，`localOverrides` 只回放开发模式编辑器明确修改的字段，`seedIds` 区分从代码删除的内置条目和用户新增条目。`seedRevision` 覆盖四类完整种子内容，使开发服务器热更新时当前页面立即重新读取、合并并刷新已选详情。旧 schema v3 的药物覆盖记录会迁移到通用结构；更早格式没有完整来源信息，首次升级遵循 [本地数据说明](local-data.md) 中的数据保护边界。删除疾病时，操作层会在仍有关联案例的情况下抛出 `dependency-conflict`；来源删除若遇到本地案例依赖，则暂时保留被引用疾病，避免破坏交叉引用。

自动迁移写回、导入和重置会在写入前保留当前原始数据。恢复操作先验证目标备份，验证通过后才备份当前状态并写入目标；无效恢复不会改变主数据或备份集合。验证、备份或写入失败时，当前主数据不应被覆盖。完整格式和恢复规则见 [本地数据说明](local-data.md)。

## 生产只读门禁

`CAN_EDIT` 由 `import.meta.env.DEV` 决定。公开生产构建不渲染新增、编辑、删除或本地数据管理入口。对应行为由 UI 测试覆盖；这是一项界面门禁，不应被当作加密或访问控制系统。

## 测试分层

- `node:test`：搜索、数据验证、静态链接、迁移、备份和导入导出纯逻辑；
- `Vitest`、Testing Library 与 axe：风险提示和普通结果抑制、生产只读入口、页面与详情焦点、dialog 键盘生命周期和基础无障碍扫描；
- 构建检查：确认生产产物存在并排除私有目录或本地路径引用。

首页视觉、页面转场观感、响应式布局、纸飞机时间线、真实滚动和多浏览器差异仍依赖真实浏览器回归。自动化测试以当前前端为对象，不能为了复用旧测试恢复已经删除的欢迎页或平行旧界面。

## 构建与部署

`npm run verify` 依次执行数据校验、静态链接校验、全部测试、生产构建和构建产物检查。普通 Pull Request 以 `dev` 为目标，CI 只运行 `Verify`；`Branch policy` 仅在目标为 `main` 的晋级 Pull Request 上运行，并要求来源是同仓库的 `dev`。只有 `main` 推送或明确的手动工作流在验证通过后上传并部署 GitHub Pages。

外部资源的网络可达性由每周工作流检查，不进入普通 Pull Request 门禁，避免第三方站点波动阻断工程变更。国家卫生健康委员会首页会对 CI 请求稳定返回带 `WZWS-RAY` WAF 签名的 HTTP 412 challenge；已观察到历史 `-w-waf` 和当前 `-waf01…` 两种节点标识。检查器仅在“精确首页 URL + 412 + 两种已确认 WAF 节点签名之一 + 未重定向”同时成立时报告 `ACCESS-BLOCKED` 警告，不把它伪装成可达。其它 URL、宽泛 `waf` 字样、缺少签名的 412、404、5xx 和网络错误仍会使检查失败。
