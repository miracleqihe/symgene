# 前端架构

## 应用入口与组合

`src/main.jsx` 只负责加载全局样式并将 `App` 挂载到根节点。`src/app/App.jsx` 组合页面，维护导航、搜索、当前词条、编辑器和本地数据面板的全局状态。

主要职责分布：

- `src/pages/`：欢迎页、首页、四类目录页面；
- `src/components/layout/`：顶部栏、侧边栏和页面标题；
- `src/components/search/`：描述式搜索界面；
- `src/components/knowledge/`：目录行、详情和案例展示；
- `src/components/editor/`：开发模式词条编辑器；
- `src/components/localData/`：开发模式数据管理面板；
- `src/hooks/`：快捷键、模态框焦点和本地知识状态；
- `src/storage/`：迁移、校验边界、备份、导入、导出和重置。

页面组件不读取原始 `localStorage` 键，也不实现迁移或文件解析。编辑器只提交结构化词条，最终写入由存储 hook 和存储层完成。

## 数据模块

正式种子由 `src/data.js` 汇总药物、疾病、案例和资源模块。`cloneSeed()` 为运行时和验证脚本提供隔离副本。数据验证器位于 `src/validation/dataValidation.js`，命令行入口为 `scripts/validate-data.mjs`。

疾病、药物、案例、风险词、搜索扩展与评分属于医学或医学相关内容。修改这些内容时必须进行单独的内容审核，不能把工程重构当作内容变更的授权。

## 搜索与风险提示数据流

首页把原始描述和当前知识数据传给 `matchKnowledge()`：

1. 原始查询用于分词和风险识别；
2. 规范化文本用于空查询判断和不区分大小写的比较；
3. 疾病按既有字段权重和概念扩展评分；
4. 案例只在关联疾病命中时参与排序；
5. 关联药物作为后续资料呈现，不作为首要搜索结果；
6. `critical` 风险会抑制普通疾病、案例和药物结果。

搜索只在浏览器内运行，不等于诊断。风险规则仍是关键词规则，不能可靠理解否定、时间、主体或复杂语境。

## 存储边界

`useLocalKnowledge()` 是 React 与存储层之间的接口。存储实现位于：

- `constants.js`：主键、版本和备份上限；
- `migrations.js`：信封格式、旧格式兼容、种子合并和 tombstone；
- `operations.js`：词条新增、修改和删除；
- `storage.js`：读写、迁移前备份、恢复和重置；
- `importExport.js`：5 MB 文件限制、导出格式、导入解析与摘要。

旧格式迁移不根据当前种子反推历史删除；用户新增和修改优先保留，当前种子的新词条正常补入。删除疾病时，操作层会在仍有关联案例的情况下抛出 `dependency-conflict`，避免静默级联删除案例。

自动迁移写回、导入和重置会在写入前保留当前原始数据。恢复操作先验证目标备份，验证通过后才备份当前状态并写入目标；无效恢复不会改变主数据或备份集合。验证、备份或写入失败时，当前主数据不应被覆盖。完整格式和恢复规则见 [本地数据说明](local-data.md)。

## 生产只读门禁

`CAN_EDIT` 由 `import.meta.env.DEV` 决定。公开生产构建不渲染新增、编辑、删除或本地数据管理入口。对应行为由 UI 测试覆盖；这是一项界面门禁，不应被当作加密或访问控制系统。

## 测试分层

- `node:test`：搜索、数据验证、静态链接、迁移、备份和导入导出纯逻辑；
- Vitest + Testing Library：欢迎流程、导航、搜索、目录、只读门禁、编辑和文件交互；
- axe-core：关键页面、风险提示、编辑器和本地数据面板的自动可访问性基线；
- 构建检查：确认生产产物存在并排除私有目录或本地路径引用。

自动化可访问性测试禁用 jsdom 无法可靠计算的颜色对比规则；颜色、标题语义和真实浏览器键盘操作仍需人工检查。

## 构建与部署

`npm run verify` 依次执行数据校验、静态链接校验、全部测试、生产构建和构建产物检查。Pull Request 只运行验证。只有 `main` 推送或明确的手动工作流在验证通过后上传并部署 GitHub Pages。

外部资源的网络可达性由每周工作流检查，不进入普通 Pull Request 门禁，避免第三方站点波动阻断工程变更。
