# 三家医院社交证据验证试点

状态：**LOCAL REVIEW ONLY / NOT APPROVED FOR PUBLICATION**

基线日期：2026-09-01

## 1. 目的

本试点验证“机构实体匹配 → 服务经历识别 → 风险分流 → 人工审阅 → 匿名维度
聚合”是否可靠。它不评价医院好坏，不验证医学结论，不生成医院评分，也不把社交
平台样本视为患者总体。

试点机构：

- 上海市精神卫生中心
- 武汉市精神卫生中心
- 北京大学第六医院

## 2. 候选变化及证据

初版程序只检查评论本身是否包含敏感标记，得到 152 条普通候选，其中三家试点
机构占 140 条。进一步审计发现，大部分评论依赖所属内容进行机构归因，而评论的
上文可能包含直接标识符、高风险个人披露、辱骂或医学主张。

修正后的流程先把上文风险沿证据链传递给评论，普通候选降为 81 条。真实浏览器
抽查随后发现，一条普通候选仍包含医务人员姓名和具体治疗经历。流程现已进一步
遮盖疑似医务人员姓名，并将姓名、具体治疗细节及依赖这些上文的评论分流到受限
研究区。普通候选最终降为 32 条，其中：

| 机构 | 普通候选 | 正文直接匹配 | 上文语境匹配 |
| --- | ---: | ---: | ---: |
| 上海市精神卫生中心 | 21 | 7 | 14 |
| 武汉市精神卫生中心 | 3 | 2 | 1 |
| 北京大学第六医院 | 3 | 2 | 1 |
| 其他三家机构 | 5 | 4 | 1 |

被降级的记录没有删除，仍留在本地受限研究区；它们不进入普通审阅页面。该变化
说明候选数量本身不是质量指标，完整证据链比评论单句判断更重要。

## 3. 标准审阅队列

`scripts/research/build-review-pilot.mjs` 生成 87 条本地队列：

| 队列 | 数量 | 用途 |
| --- | ---: | --- |
| 三家机构普通候选 | 27 | 测量机器候选的准确性 |
| 三家机构负例抽查 | 30 | 检查服务经历规则是否排除过多 |
| 未匹配机构漏判抽查 | 30 | 检查别名或实体解析是否漏判 |

队列不包含程序已检测到的高风险披露、直接标识符、疑似医务人员姓名、具体治疗
细节、辱骂、广告、公共事务敏感或受限上下文记录。语境归因只显示触发实体匹配
的医院名称或别名，不再载入整篇上文。遮盖后的文本仍然属于敏感研究数据，只能
存在于 git 忽略的 `work/`。自动检测不是匿名化保证，审阅者仍需检查漏判的人名、
间接标识符和精确就诊轨迹。

## 4. 标注字段

### 4.1 医院归因 `entityDecision`

- `correct`：正文或安全上下文明确支持所列机构。
- `incorrect`：提到另一机构、通用名称或语境无法支持归因。
- `uncertain`：信息不足，需要进一步核验。

搜索关键词、平台标题栏和程序建议本身都不能证明机构归属。

### 4.2 服务经历 `experienceDecision`

- `firsthand`：作者明确描述本人接受服务。
- `accompanied`：作者明确描述陪同家人或朋友接受服务。
- `not_experience`：新闻、科普、转述、广告、一般讨论或无实际接触。
- `uncertain`：主体或经历无法判断。

### 4.3 服务维度 `aspects`

- `access_and_wait`：预约、挂号、排队、等待、交通。
- `cost_and_billing`：费用、收费说明、医保或报销。
- `staff_interaction`：沟通、尊重、态度和信息解释。
- `process_and_information`：就诊步骤、检查、隐私和告知。
- `environment_and_facilities`：环境、卫生、诊室和设施。
- `continuity_and_follow_up`：复诊、随访、转诊和后续安排。
- `self_reported_outcome`：用户自述变化；只作风险标记，不解释为疗效。
- `other`：与服务相关但不属于以上字段。

### 4.4 隐私 `privacyDecision`

- `clear`：审阅者未发现残留的直接或明显间接标识符。
- `residual_identifier`：仍可能识别个人、账号、联系方式或精确就诊轨迹。
- `uncertain`：无法确认。

`clear` 只表示本次人工检查未发现，不等于不存在重识别风险。

### 4.5 聚合候选 `aggregationDecision`

- `include`：机构正确、属于本人或陪诊服务经历、隐私为 `clear`，且内容仅支持非
  医学服务维度。
- `exclude`：任一必要条件不成立。
- `uncertain`：需要第三人裁决或权威来源核验。

`include` 仍不代表允许公开。发布还需要来源授权、样本规则、平台偏差、机构纠错
和产品/隐私审查。

## 5. 审阅程序

1. 两名审阅者使用不同、非真实姓名的代号。
2. 两人独立完成同一队列，不交换中间标签。
3. 默认不展开机器判断，先根据文本和安全上下文独立判断。
4. 页面不会使用 `localStorage`；标签只保存在内存，需定期导出。
5. 导出的标签文件不包含帖子正文，但仍只保存在本地。
6. 使用 `scripts/research/analyze-review-labels.mjs` 计算一致率与 Cohen's kappa。
7. 分歧由第三名审阅者裁决；不能用多数表决替代来源核验。

一致率衡量的是标注规则是否清楚，不等于数据真实、有代表性或可以发布。

## 6. 本地运行

生成队列：

```bash
node scripts/research/build-review-pilot.mjs \
  --input work/social-research/2026-09-01/normalized-private.jsonl \
  --output-dir work/social-evidence-pilot/2026-09-01
```

启动只监听本机的审阅页：

```bash
node scripts/research/serve-review-pilot.mjs \
  --queue work/social-evidence-pilot/2026-09-01/review-queue-private.json \
  --port 43219
```

两名审阅者导出标签后生成一致性报告：

```bash
node scripts/research/analyze-review-labels.mjs \
  --labels work/social-evidence-pilot/reviewer-a-labels.json \
  --labels work/social-evidence-pilot/reviewer-b-labels.json \
  --output work/social-evidence-pilot/agreement-report.json
```

## 7. 完成门槛

本试点结束时必须报告：

- 两名审阅者各自完成数和共同完成数；
- 四个分类字段的一致率与 Cohen's kappa；
- 服务维度的精确一致率和平均 Jaccard；
- 机器候选中错误机构、非服务经历和隐私残留的比例；
- 负例抽查中的漏判比例；
- 每个平台和每家机构的样本分布；
- 仍需产品、隐私、医学或来源授权决定的事项。

人工审阅完成前，不设定“达标即上线”的自动阈值，也不训练模型。阈值必须根据
实际错误类型、可接受风险和审阅成本另行评审。

## 9. 产品字段结论

三家官网已经能够支持第一版“如何找到并预约服务”的资料卡，但不能支持费用、
等待时间、远程服务或无障碍能力的完整比较。下一步如实现原型，应将字段分成：

- `verified`：有当前官方页面直接支持；
- `dynamic`：只链接官方实时入口，不复制具体排班或号源；
- `notVerified`：明确显示尚未核验，不从社交评论推断；
- `lastVerifiedAt`：按字段记录核验日期，而不是只给整张卡一个日期。

社交平台审阅结果只能补充“用户经常关心哪些服务字段”，不能覆盖或纠正官方事实。
